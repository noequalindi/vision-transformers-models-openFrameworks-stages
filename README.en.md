# vision-transformers-models-openFrameworks-stages

[Español](README.md) | **English**

For the coding class: [from model output to interaction in OF](docs/GUIA_CODIGO_OF.md) (Spanish).

Two local examples for learning how to build interactions from model responses.
This folder is the repository root: it includes the Python code, the `ofxLocalAI`
addon, the sketches, and the class materials. The application interfaces and the
linked supplementary guides are in Spanish.

| Example | Model | Input → output | Runtime and connection |
| --- | --- | --- | --- |
| [visionViT](visionViT/README.md) | Google ViT Base, 16 × 16 patches | Image → five categories with scores | Python/PyTorch, HTTP/JSON at `127.0.0.1:8768` |
| [visionChat](visionChat/README.md) | Qwen3-VL 2B Instruct | Image + question → text | Ollama, HTTP/JSON at `127.0.0.1:11434` |

OF captures images and draws the interface; `ofxLocalAI` sends requests without
blocking rendering; each runtime runs its model. ViT classifies the whole image;
Qwen answers questions about it. These examples do not generate images or video,
and do not perform tracking.

### visionViT: image → categories

ViT classifies the whole image and displays the five categories with the highest
scores. In this screenshot, the top category is `tabby, tabby cat` (47.6%). The
bars represent hypotheses about the image, not objects or their positions.

![visionViT interface: a cat in the snow and five categories with their scores](assets/screenshots/vision-vit-cat.png)

### visionChat: image + question → description

Prompt used in the screenshot: **“Describe el animal, su pelaje y el entorno en una frase corta.”**
(“Describe the animal, its coat, and its surroundings in one short sentence.”)
Qwen3-VL receives the photo and the text, then generates the description shown in OF.
A typing animation reveals the response after the complete text has been received.

![visionChat interface: cat photo, question, and description generated by Qwen3-VL](assets/screenshots/vision-chat-cat.png)

## 1. Install the environment and download the models

Download the complete folder and put it where you intend to use it. Open a
terminal **in this folder** and run the command for your operating system:

| System | Command |
| --- | --- |
| macOS | `bash install_env_mac.command` |
| Linux | `bash install_env_linux.sh` |
| Windows, CMD | `install_env_windows.cmd` |
| Windows, PowerShell | `.\install_env_windows.cmd` |

The scripts set up Python 3.11 through uv, install Ollama if needed, create
`.venv-vision`, install the libraries, and download **only ViT and Qwen3-VL**.
You do not need to install the LLM class project. On Windows, complete the Ollama
setup wizard when it opens. An existing Ollama installation must be
**version 0.12.7 or later**.

ViT is stored in `models/vit-base-patch16-224/`; Qwen is stored in Ollama's model
storage. The installer checks ViT inference and preloads Qwen with a five-minute
keep-alive period. Ollama remains running. If the same model is already installed
in Ollama, it is reused. Initial setup requires internet access; later queries
run locally.

Do not move `.tools` or `.venv-vision` between folders or computers: they contain
local paths. To change locations, download/copy the source files and install
there. The `bash` commands also work if the script has lost its executable permission.

## 2. Start the service required by the example

For **visionViT**, run the following and leave the terminal open:

| System | Command |
| --- | --- |
| macOS | `bash start_vision_mac.command` |
| Linux | `bash start_vision_linux.sh` |
| Windows | `start_vision_windows.cmd` (PowerShell: `.\start_vision_windows.cmd`) |

Wait for the Uvicorn message and check [ViT's status](http://127.0.0.1:8768/health).
It should return `ready: true`. Press Ctrl+C to stop the service. To select CPU,
append `--device cpu` to the startup command.

For **visionChat**, keep Ollama running. It does not need the ViT server.
After restarting your computer, open Ollama again. `ollama list` shows downloaded
models; `ollama ps` shows models currently loaded into memory.

## 3. Copy the examples into openFrameworks

Install openFrameworks and its compiler separately. These examples use OF 0.12.1.

1. Copy the **entire** `ofxLocalAI/` folder to `OF/addons/ofxLocalAI/`.
   If you already used the LLM class project, update the entire addon: this version
   adds `classifyImage()` and `ofxVisionImage.h` while keeping the chat API.
2. Copy `visionViT/` and `visionChat/` to `OF/apps/myApps/`.
3. In Project Generator, import/update each existing project. If it shows separate
   fields, use **Project path = `OF/apps/myApps`** and **Project name = `visionViT`**
   or **`visionChat`**. Select the **ofxLocalAI** addon.
4. Leave Additional source paths empty and click **Update**. The generated project
   must use the example's `src/ofApp.cpp`; do not create a template inside a nested folder.
5. Build and run the generated project. On macOS/Linux, from its folder inside OF:

```sh
make Release -j4
make RunRelease
```

On Windows, open and build with the IDE supported by your OF distribution.
These examples do not need OSC or Box2D. You edit and build the copy in
`OF/apps/myApps`; changes made in this repository must be copied there before rebuilding.

## 4. Try and modify the examples

- **O** loads a JPG/PNG; **C** activates the camera; **Enter / ANALIZAR** sends a snapshot.
- **RECARGAR EJEMPLO** (Reload example) restores the included image and clears the response.
- In ViT, **P** draws a teaching grid of patches, not an attention map.
- In Chat, type a question and send it; **Esc** leaves the text editor so you can use shortcuts.
  The typing animation starts after the complete response arrives.
- **R** shows sample data marked *sin inferencia* (without inference); it does not test the connection.

Edit `response()` in each `src/ofApp.cpp` to turn the result into an interaction;
edit `draw()` to change its appearance. The service address and camera settings
are in each sketch's `bin/data/connection.json`.

## Models, download sizes, and local requirements

| Model | Model weights on disk | Estimated total system RAM |
| --- | --- | --- |
| `google/vit-base-patch16-224` (FP32) | 346 MB | 8 GB as a starting point |
| `qwen3-vl:2b-instruct` (Q4_K_M) | 1.89 GB | 8 GB with little headroom; 16 GB recommended |

The weights total approximately **2.24 GB**, measured locally on October 5, 2026.
Download size is not the same as memory usage during inference. These RAM figures
are estimates for using one model at a time, not verified minimum requirements on
8 GB computers. Allow **15 GB of free disk space for CPU/macOS** or **25 GB with
PyTorch CUDA**, in addition to OF and its compiler.

- **macOS 14 or later:** Apple Silicon can use Metal/MPS; Intel can use CPU.
- **Windows 10 22H2/11 or 64-bit Linux:** CPU; compatible NVIDIA hardware can use CUDA.
- **GPU optional:** ViT selects CUDA/MPS/CPU based on availability; Ollama separately
  decides where to run Qwen. CPU inference means longer waits.
- The installer uses Python 3.11, Torch 2.8.0 (2.2.2 on Intel macOS), and Transformers
  4.57.6. Windows/Linux use CUDA 12.8 wheels if `nvidia-smi` is found, or CPU wheels
  otherwise. Actual GPU availability depends on the driver and PyTorch.

More device options are in [the technical guide](vision/README.md#gpu-y-cpu) (Spanish).
References: [Google ViT](https://huggingface.co/google/vit-base-patch16-224),
[Qwen3-VL on Ollama](https://ollama.com/library/qwen3-vl:2b-instruct),
[Ollama on macOS](https://docs.ollama.com/macos), [Windows](https://docs.ollama.com/windows),
and [GPU support](https://docs.ollama.com/gpu). Both models have Apache 2.0 licensed
weights; local queries require neither an API key nor a per-query payment.

After installation (on Windows, replace the Python path with `.venv-vision\Scripts\python.exe`):

```sh
.venv-vision/bin/python -m pip install -r requirements-dev.txt
.venv-vision/bin/python -m pytest -q
# macOS: check C++ syntax against your installed SDK:
.venv-vision/bin/python tools/check_of_headers.py /path/to/of_v0.12.1_osx_release
```
